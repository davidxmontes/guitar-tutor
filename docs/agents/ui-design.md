# UI design

Aim for a calm, tasteful music workspace. The instrument and musical relationships
should dominate; controls should support the task quietly.

- Start with the whole screen and the learner's primary action. Keep the playing
  surface visible at a typical desktop viewport, with useful stacking on mobile.
- Prefer direct manipulation: drag chords to reorder, select notes on the neck,
  and edit the selected object in place. Provide keyboard and touch alternatives.
- Show the essentials first. Put occasional editing options in a disclosure or
  contextual menu. Use one coherent selected-object panel instead of duplicate
  diagrams and forms.
- Keep repeated items visually quiet. Reveal secondary actions on hover/focus,
  with discoverable touch access; preserve accessible names and focus indicators.
- Use consistent spacing, restrained borders, and a clear type hierarchy. Remove
  redundant headings and instructions before shrinking text or touch targets.
- Empty space should clarify grouping, not separate related controls from their
  music. Judge components together rather than polishing isolated cards.
- Before finishing, inspect the actual screen at desktop and mobile sizes. Check
  the primary task, expanded states, keyboard operation, and overflow. Passing
  tests alone does not establish that a layout feels pleasant.

For a progression strip, prefer draggable chord cards with a discreet contextual
remove action over a permanent row of move/edit/delete buttons on every card.
