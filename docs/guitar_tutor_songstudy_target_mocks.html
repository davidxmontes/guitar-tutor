What I mean by “Overview + Focus” vs “Full Tab”

Same song, same selection, same core tab renderer. The difference is composition: Overview + Focus is the learning workspace; Full Tab is the dense reading/navigation view.

Desktop Overview + Focus Desktop Full Tab Physical chord strip Mobile What to tell frontend

Desktop target: Overview + Focus

This is the screen I would make the default when the user opens a song.

Key idea: the song map stays compact, the selected 2–4 measures are the center of gravity, the fretboard supports the explanation, and Tutor lives beside the thing being explained.

This is not another learning dashboard. It is a dense, readable whole-song view for scanning and navigating.

Key idea: remove the permanent fretboard and Tutor from this view. Give the tab the width. Selecting measures reveals lightweight actions that send the range back into Focus, Practice, or Tutor.

What I would tell the frontend team now

Don't throw away what they built. Keep their measure selection, tab renderer, whole-track loading, section markers, active beat, and fretboard synchronization. Restructure the composition around those pieces.
Overview + FocusCompress the 97-measure grid into a compact section-aware overview. Make m34–37 the main workspace.
Desktop TutorReserve a right rail for Tutor/context while focused music is visible. It can be collapsible later.
FretboardSupporting relationship view by default—not a permanent half-screen canvas.
Full TabKeep it full-width and dense. Selection provides Focus / Practice / Ask Tutor actions.
Chord shapesPlace the ordered physical diagram strip between focused tab and fretboard. Use V1’s diagram as visual inspiration, rebuilt for exact V2 positions and tuning.
