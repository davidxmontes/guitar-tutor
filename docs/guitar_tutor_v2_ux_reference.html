Guitar Tutor V2 UX reference

One musical workspace. Branch when ideas become worth exploring.

This reference turns the product spec into concrete screen hierarchy and interaction flow for desktop and iPhone. It is intentionally not pixel-perfect styling; it defines the major regions, responsive behavior, and transitions the frontend should preserve.

The user owns navigation. The tutor owns attention.
Fretboard convention

All fretboard mocks use six strings and an explicit fret window. String labels, fret numbers, and position markers make it clear where on the neck the learner is working. Active, upcoming/comparison, and context notes use a consistent green-led visual language.

Product rules the UI should make obvious

Artifact firstAlways make the current musical thing obvious: song, progression, concept, or exercise.
Show sequencesSongs and progressions remain visible as a whole; detail views explain the selected part.
Branch explicitlyAI suggestions stay candidates until the user chooses Save, Apply, or Explore.
AI is additiveRaw tab/ChordPro remain source truth. AI focus and enrichment sit on top.

9. Mobile coverage in the current tickets

AreaCurrent ticket coverageRecommendation
Branch navigationDefined
Desktop tabs / mobile workspace switcher is explicitly in the branching ticket.		Keep as-is; use the mobile switcher shown above as the UX reference.
Voicing candidatesDefined
Ticket already says desktop can show several candidates and mobile should use a compact/swipeable representation.		Reference horizontal swipe/card behavior explicitly.
Practice FocusDefined
Practice + optional Focus presentation is in the ticket.		Add that Focus must be comfortable for iPhone/music-stand use.
SongStudy mobile layoutPartial
Responsive behavior is implied, but whole-song map + focused measures is not described specifically for mobile.		Add: horizontally scrollable overview, 1–2 focused measures, fretboard below, tutor as sheet/panel.
Tutor presentation on mobileGap
The tickets define semantic tutor behavior but not its mobile presentation.		Add: tutor uses a bottom sheet/drawer so it does not permanently steal vertical space from tab/fretboard.
Progression mobile layoutPartial
Candidate responsiveness is covered, but the whole progression workspace hierarchy is not.		Add: horizontal progression strip → selected chord/transition → fretboard → tutor actions.
Enhancement UI on mobileGap
Enrichment behavior is defined, but not how annotations fit a small viewport.		Add: annotations live mainly in the song map / selected measure detail, not as permanent large panels.
Implementation target: preserve this hierarchy and these transitions. Styling can evolve; the user should never have to infer where they are, what changed, or how to get back.
